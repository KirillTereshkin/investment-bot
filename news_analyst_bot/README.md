# 📈 News Analyst Bot — новостной аналитик российского рынка

Telegram-бот, который по расписанию собирает экономические новости российского рынка из RSS,
прогоняет их через DeepSeek (OpenAI-совместимый API) и присылает краткий торговый прогноз:
резюме рынка, 1–4 идеи с горизонтом и триггером отмены, «урок дня» и — если задан токен —
предупреждения по уже открытым позициям в Tinkoff Инвестициях.

## Как это работает

```
APScheduler
   ├── 10,12,14,16,18,20 МСК → run_analysis
   └── 21:00 МСК             → check_predictions (проверка отработки идей)

run_analysis:
news/collector.py  →  6 RSS-источников (независимо, с ретраями)
        │                • RBC News (rssexport.rbc.ru)
        │                • CBR (cbr.ru/rss/RssNews)
        │                • TASS, Interfax, Kommersant, Investing.com
        ▼
news/dedup.py      →  SHA1(нормализованный заголовок) + Jaccard > 0.8
        ▼
collector.build_digest()  →  до 25 строк, round-robin по источникам
        ▼
market/quotes.py   →  котировки: ЦБ РФ (USD/RUB, CNY/RUB, EUR/RUB, ключевая ставка, кэш 24 ч)
        │                и MOEX ISS (IMOEX); падение источника → SQLite → fallback config.py
        ▼
broker/tinkoff.py  →  открытые позиции (только чтение, кэш 5 минут)
        ▼
ai/client.py       →  DeepSeek (JSON-ответ, 2 ретрая, temperature 0.3)
        ▼
storage/db.py      →  SQLite: runs, market_snapshots, predictions, cache
        ▼
bot/notifier.py    →  Telegram (HTML, разбивка по 3900 символов, fallback на плоский текст)

check_predictions:
идеи с истёкшим горизонтом → MOEX ISS (текущая цена) → ±1% → hit/miss → /accuracy
```

Ключевые свойства:

* падение одного источника не роняет прогон — статус каждого источника попадает в сообщение;
* котировки необязательны: при недоступности MOEX ISS/ЦБ берутся последние значения из SQLite,
  затем fallback из `config.py` (с `WARNING` в лог);
* Tinkoff опрашивается **только на чтение** (счета и позиции): ордера не выставляются и не отменяются.
  Без токена или без библиотеки бот работает как раньше, просто без блока «По вашим позициям»;
* анализ всегда один: `/now` во время планового прогона получит ответ «уже выполняется»;
* если новостей за окно нет — DeepSeek не вызывается (экономия токенов);
* любой ответ модели экранируется (`html.escape`), разметка Telegram безопасна;
* при отклонении HTML-разметки Telegram сообщение автоматически переотправляется плоским текстом;
* логи идут в stdout и в `bot.log` с ротацией (5 МБ × 3 файла).

## Установка

```powershell
cd c:\Projects\investment-bot\news_analyst_bot

python -m venv .venv
.\.venv\Scripts\Activate.ps1

pip install -r requirements.txt
```

> Если PowerShell блокирует `Activate.ps1` («выполнение сценариев отключено»), выполните
> `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` в текущем окне
> или используйте `.\.venv\Scripts\python.exe` напрямую, без активации.

> `tinkoff-investments` в `requirements.txt` нужен только для блока позиций и `/portfolio`.
> Если пакет недоступен в вашем окружении (PyPI/зеркало) — закомментируйте строку: бот продолжит
> работать и покажет в статусе «💼 Tinkoff: ⏭️ библиотека не установлена».
> Альтернатива для позиций — MCP-сервер `t-bank-invest-mcp-read-only` (запуск через `uvx`).

## Настройка .env

```powershell
Copy-Item .env.example .env
notepad .env
```

| Переменная             | Обязательна | Где взять |
|------------------------|-------------|-----------|
| `TELEGRAM_BOT_TOKEN`   | да          | [@BotFather](https://t.me/BotFather) → `/newbot` |
| `TELEGRAM_CHAT_ID`     | да          | напишите боту, затем откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и возьмите `chat.id` (для личных сообщений — ваш user id) |
| `DEEPSEEK_API_KEY`     | да          | https://platform.deepseek.com/api_keys |
| `TINKOFF_INVEST_TOKEN` | нет         | https://www.tinkoff.ru/invest/settings/api/ — токен **только для чтения** |
| `TINKOFF_ACCOUNT_ID`   | нет         | id счёта, если нужно смотреть не первый брокерский |

Без первых трёх переменных `main.py` не стартует и печатает, чего именно не хватает.
Без `TINKOFF_INVEST_TOKEN` бот просто не добавляет в промпт блок позиций.
Котировки (MOEX ISS, ЦБ РФ) ключей не требуют — работают «из коробки».

## Проверка перед запуском

В проекте есть смоук-тест (`_smoke_test.py`) — от дедупликации и парсинга RSS до полного
`run_analysis` с заглушкой бота, котировок MOEX/ЦБ, разбора ответа и проверки идей:

```powershell
.\.venv\Scripts\python.exe _smoke_test.py
```

Особенности:

* Telegram и DeepSeek из теста **не вызываются**: используется поддельная `Bot` с мок-сессией;
* Tinkoff проверяется на фейковом SDK (`sys.modules`) — реальный токен и библиотека не нужны;
* БД теста изолирована — `_smoke.sqlite3`, рабочий `news_bot.sqlite3` не трогается;
* секция `live` реально ходит в RSS-источники и в MOEX ISS/ЦБ РФ, поэтому нужен интернет;
* если в `.env` заполнен `DEEPSEEK_API_KEY`, сквозной тест сделает **один реальный запрос**
  к DeepSeek — уберите ключ, если не хотите тратить токены.

Ожидаемый финал: `Выполнено проверок: 189` и `ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ`, код выхода `0`
(при `ПРОВАЛЕНО ПРОВЕРОК` код выхода `1`).
Если консоль в cp1251 и тест падает на юникоде — запускайте командой `chcp 65001` перед стартом.

## Структура проекта

```
news_analyst_bot/
├─ main.py              точка входа: логирование (rotating), БД, bot, scheduler, polling
├─ config.py            настройки и секреты (.env), fallback-котировки, хелперы времени МСК
├─ requirements.txt     aiogram, openai, feedparser, APScheduler, requests, python-dotenv, tinkoff-investments
├─ .env.example         образец переменных окружения
├─ _smoke_test.py       смоук-тест (189 проверок), запускается вручную
├─ ai/
│  ├─ prompts.py        системный промпт (правила 1–10), блок позиций, JSON-схема ответа
│  └─ client.py         DeepSeek: JSON-режим, ретраи, парсинг ответа
├─ news/
│  ├─ collector.py      RSS-источники, ретраи, окно сбора, дайджест
│  └─ dedup.py          нормализация заголовков, SHA1, Jaccard
├─ market/
│  └─ quotes.py         ЦБ РФ (курсы, ключевая ставка 24 ч), MOEX ISS (IMOEX, цены тикеров)
├─ broker/
│  └─ tinkoff.py        Tinkoff Invest, только чтение: счета, позиции, FIGI→тикер
├─ predictions/
│  └─ horizon.py        горизонт идеи → дата проверки, оценка факта (±1%), hit/miss
├─ bot/
│  ├─ notifier.py       формат сообщений и безопасная отправка
│  └─ handlers.py       /start /now /last /stats /accuracy /portfolio /schedule /help
├─ scheduler/
│  └─ jobs.py           CronTrigger, run_analysis, check_predictions, get_market_snapshot
└─ storage/
   ├─ db.py             SQLite: runs, market_snapshots, predictions, cache, агрегаты
   └─ migrations.py     создание таблиц и добавление новых колонок (идемпотентно)
```

> Пакет интеграции назван `broker`, а не `tinkoff`, намеренно: SDK ставится как top-level пакет
> `tinkoff`, и локальная одноимённая папка перехватывала бы импорт `from tinkoff.invest import Client`.

## Схема SQLite

| Таблица            | Назначение |
|--------------------|------------|
| `runs`             | прогоны анализа: статусы источников, статус DeepSeek, дайджест, ответ модели, статус Tinkoff, снимок котировок |
| `market_snapshots` | котировки на момент прогона: USD/RUB, CNY/RUB, EUR/RUB, IMOEX и изменение, ключевая ставка, `source_status` (JSON: что ответило, что упало) |
| `predictions`      | идеи: тикер, направление, уверенность, горизонт, цена входа, `check_at`, цена и факт на проверке, `hit` (1/0/NULL) |
| `cache`            | Tinkoff: снимок позиций (TTL 5 мин) и маппинг FIGI→тикер (TTL 7 дней) |

Как считается точность (`/accuracy`, окно 30 дней):

* `отработано` — проверенные идеи «лонг»/«шорт» (hit = 0 или 1);
* идеи «наблюдать» проверяются, но в точность не входят (hit = NULL);
* фактическое направление: рост / падение / боковик при пороге ±1% (`PREDICTION_FLAT_THRESHOLD_PCT`);
* идеи без цены входа (ОФЗ, фьючерсы, валютные пары) сохраняются, но не проверяются.

## Источники котировок (что реально используется)

| Данные | Источник | Особенности |
|--------|----------|-------------|
| USD/RUB, CNY/RUB, EUR/RUB | https://www.cbr-xml-daily.ru/daily_json.js | JSON-зеркало официального XML ЦБ; кодировка UTF-8, при необходимости читается как windows-1251 |
| Индекс MOEX (IMOEX) | MOEX ISS: `.../index/boards/SNDX/securities/IMOEX.json` | колонка `CURRENTVALUE`, изменение — `LASTCHANGEPRC` (в ТЗ упоминалась `LASTCHANGEPRCNT`; у индексов она называется иначе — проверяются оба варианта) |
| Ключевая ставка | сначала `cbr.ru/scripts/XML_key_rate.asp`, затем HTML-таблица `cbr.ru/hd_base/KeyRate/` | кэш 24 ч; на 15.10.2026 XML-эндпоинт отдаёт HTML вместо XML, поэтому рабочей веткой является таблица (обе ветки кода сохранены) |
| Цена тикера | MOEX ISS: борды `TQBR` (акции) и `TQTF` (фонды) | задержка ~15 мин, ключ не нужен; ОФЗ/фьючерсы/валютные пары тут не торгуются |

Все запросы: `timeout=10`, 2 повтора с паузой 3 с. Падение источника → последнее значение из
`market_snapshots` → `fallback` из `config.py` + `WARNING` в лог. Прогон при этом не падает.
